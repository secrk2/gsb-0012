# 工瞳 · 工地人员实名制与不安全行为预警平台

面向住建场景的工地安全产品骨架。当前包含三大模块：**工地作战台**（在场漏斗 / 今日应培训 / 隐患 / 告警红点 / **本周出勤双口径**）、**人员档案**（实名制状态机 / 姓名脱敏 / 查看留痕）与**出勤打卡与分账**（闸机+手机定位多源合并、出勤判定、周/月甘特、合同版本单价 × 出勤工日的冻结分账），支持离线作业与五类角色数据隔离。

## 一键启动

```bash
docker compose up --build
```

- 前端（Nginx，反代 `/api` → 后端）：http://localhost:8105
- 后端（Go，SQLite 落盘在 `gt-data` 卷）：http://localhost:7105/api/healthz

首次启动自动灌入演示数据：**3 个工地、21 名人员（覆盖待入场/在场/请假离场/退场/黑名单全部状态）、6 个账号、培训/隐患/告警数据**。

## 需求点对照

| 需求 | 实现 |
|---|---|
| 人员状态机 | `待入场→在场→请假离场→退场→黑名单`，有向边见 `backend/models.go`；非法回退返回 409 + 中文原因（如「已退场，状态不可回退」） |
| 实名制入场 | `待入场→在场` 必须同时完成刷脸 + 身份证核验，否则 422 拦截 |
| 姓名脱敏 | 列表/详情默认 `张* · 工号`，身份证/手机号同步脱敏 |
| 查看全名 | 仅总包/监理，弹窗二次确认 + 必填理由，写 `reveal_logs` 留痕，监管员可追溯 |
| 作战台 | 在场漏斗、今日应培训、未闭环隐患、告警红点（点击消红点/全部已读） |
| 响应式 | 1440 三栏 / 1024 两栏 / 390 单栏 + 底部导航（断点 1280/768） |
| 数据隔离 | 工人越权看他人档案 → 403 错误态页面（非空白）；班组长限本班组；总包/监理限本工地 |
| 离线作业 | 离线横幅 + 缓存数据打「离线缓存·更新于 xx」戳；变更进 localStorage 队列 |
| 恢复合并 | 恢复后 `POST /api/sync/batch` 批量同步，按 `client_op_id` 幂等去重（唯一索引 + 同事务写入），状态已被他人推进的返回 `conflict` + 当前状态，前端提示并刷新 |

## 离线能力演示

1. 用 `sub_leader` 登录，打开某工人档案；
2. 浏览器 DevTools → Network → 勾选 **Offline**；
3. 顶部出现离线横幅；执行「办理请假」→ 提示「已离线排队」；
4. 取消 Offline → 自动批量同步，提示已同步/去重；
5. 若离线期间他人已变更该工人状态（可开另一浏览器操作），同步时提示冲突并按服务器最新状态合并。

## 出勤打卡与分账

### 多源打卡合并
- 来源：闸机（`gate`，多台设备）与手机定位（`mobile`）。**同人同天无论被两台闸机、还是手机+闸机打到，都只合并成一条日结论**（`attendance_days` 按 工人+日期 唯一），原始流水保留在 `attendance_punches`，按 `client_op_id` 幂等去重。
- 每日判定：按班组排班规则（上班截止/下班最早/应出勤星期/半天班）输出 **出勤 / 迟到 / 早退 / 缺勤 / 休息 / 已作废**；迟到+早退同日双标记；有效工时=首入→末出。
- 工人只能用手机给本人打卡；闸机卡由总包/监理/班组长代上报。
- 单条误打卡可作废/恢复（当日全作废→结论变「已作废」），人工可改判并锁定该日，全部写 `attendance_corrections` 留痕。

### 改出勤会动已结算月：二次确认 + 原因
- 已结算（冻结）月份的补打卡 / 作废 / 改判，首次请求返回 `409 need_confirm`，必须带 `confirm:true` + 必填原因，操作留痕；**只改出勤记录，不重算当月工资**，差额走「差额调整」单列。

### 工资分账（冻结、版本单价、部分发薪不冲销）
- 计薪 = 计薪工日 × 日单价：出勤/迟到计全工日，早退按合同折算系数；**逐天取当日生效的合同版本**。
- 合同日单价按班组设版本（`valid_from`）：**新版本只影响生效日之后，历史已结算月份冻结在原单价版本**。
- 月结算把工日/单价/金额写成快照并锁定该月出勤；重复结算被拒。
- 支持**部分发薪**（可多次），已发金额由正向发薪流水累加、**只增不减，任何重算都不冲销**；超额发放、扣减致应付低于已发均被拦截；冻结后补差/扣减走 `payroll_adjustments`，不动原快照。

### 出勤率双口径（三处文案逐字一致）
- 按出勤天：`出勤率（按出勤天）= 实际出勤天 ÷ 应出勤天`
- 按打卡工时：`出勤率（按打卡工时）= 有效打卡工时 ÷ 排班工时`
- 半天班班组两口径数值可能不同（界面有显式提示）。同一定义在 **作战台出勤卡 / 出勤打卡详情 / CSV 导出** 三处保持一致，可在页面切换，选择记忆在本地。
- 应出勤仅统计「在场」或区间内确有打卡者；请假/退场/黑名单/待入场且无打卡不计缺勤。

### 三种空/错态严格分开（不统一「暂无数据」）
1. **加载失败**：离线无缓存或服务错误（📡 重试）；2. **该人无出勤打卡**：确无流水（🧾 去补打卡）；3. **出勤打卡全作废**：有流水但全部作废（🚫 去恢复）。

### 响应式
桌面（>1280）横向甘特；**平板两栏**（≤1280，左人员右日期格子）；**手机竖向**（≤768，人员在上、日期 7 列竖排，底部导航）。

### 演示数据
种子内置：各班组排班（木工二班为半天班 一三五）、跨 7/8/9 月打卡（含双闸机+手机合并、迟到/早退/缺勤、全天作废、人工改判）、钢筋/木工/架子/机械四班组新旧两版单价、**2026-07 已发清冻结、2026-08 部分已发冻结（含一笔补差）**。

## 本地开发（不用 Docker）

```bash
# 后端（Go ≥ 1.22）
cd backend && go run .            # 监听 :7105，自动建库+种子数据

# 前端（任意静态服务器，需把 /api 代理到 7105，或直接改 js/api.js 中路径）
cd frontend/static && python3 -m http.server 8105
```

## API 摘要

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/login` | 登录（bcrypt 校验，12h 会话） |
| GET | `/api/dashboard?site_id=` | 作战台聚合 |
| GET | `/api/workers?status=&q=` | 人员列表（按角色隔离，脱敏） |
| GET | `/api/workers/{id}` / `/api/workers/me` | 档案详情 + 时间线 + 留痕 |
| POST | `/api/workers/{id}/transition` | 状态变更（状态机校验 + `client_op_id` 幂等） |
| POST | `/api/workers/{id}/reveal-name` | 查看全名（总包/监理 + 理由 + 留痕） |
| POST | `/api/sync/batch` | 离线批量同步（applied/duplicate/conflict） |
| POST | `/api/alerts/{id}/read`、`/api/alerts/read-all` | 告警消红点 |
| POST | `/api/attendance/punch` | 闸机/手机打卡（多源合并、`client_op_id` 幂等；冻结月需 confirm+原因） |
| GET | `/api/attendance/gantt` | 周/月出勤甘特 + 双口径（view/from/month/team） |
| GET | `/api/attendance/me`、`/api/workers/{id}/attendance` | 本人/单人出勤详情（甘特+原始打卡+留痕） |
| POST | `/api/attendance/punches/{id}/void`、`/restore` | 作废/恢复单条打卡（冻结月二次确认） |
| POST | `/api/attendance/adjudicate` | 人工改判日结论（冻结月二次确认+留痕） |
| GET | `/api/attendance/export` | CSV 导出（表头写明双口径定义） |
| GET/POST | `/api/contracts` | 合同日单价版本（新版本仅影响生效日后） |
| GET | `/api/payroll/months`、`/api/payroll/month` | 月历 / 月分账（冻结快照或实时试算） |
| POST | `/api/payroll/settle` | 月结算并冻结（仅总包，不可重复） |
| POST | `/api/payroll/pay` | 发薪（支持部分发、批量发清；已发不冲销） |
| POST | `/api/payroll/adjust` | 冻结月差额补差/扣减（单列留痕，不碰快照与已发） |
